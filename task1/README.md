# Задача 1, вариант 3

Уравнение Пуассона `-Δu = 1` в трапеции с вершинами
`(0,0), (3,0), (2,3), (0,3)`, на границе `u = sin(x+y)`.

Метод фиктивных областей на прямоугольнике `[-1,4]²`, пятиточечная
разностная схема, метод сопряжённых градиентов с диагональным
предобусловливателем. Четыре реализации: последовательная, OpenMP,
MPI и MPI+OpenMP. Используется C++11.

## Сборка на Полюсе

Из каталога `task1`:

```bash
module load SpectrumMPI
make all
```

Отдельные цели: `make seq`, `make omp`, `make mpi`, `make hybrid`.
Компиляторы задаются через `CXX` и `MPICXX`, по умолчанию `g++` и `mpicxx`.

## Запуск на Полюсе

Каждая команда ставит **одно задание LSF** для соответствующей реализации:

```bash
bash submit.sh seq
bash submit.sh omp
bash submit.sh mpi
bash submit.sh hybrid
```

| Реализация | Сетка | Процессов | Потоков на процесс |
|---|---|---|---|
| Последовательная | 20×20, 40×40, 80×80 | 1 | 1 |
| OpenMP | 80×80 | 1 | 1, 4, 16 |
| MPI | 80×80 | 1, 2, 4 | 1 |
| MPI+OpenMP | 80×80 | 1, 2 | 4 |

Внутри задания каждая конфигурация выполняется один раз. Всего четыре
задания очереди и 11 запусков решателей; повторных замеров нет.
Допуск остановки — `1e-8`. Все процессы одного задания размещаются
на одном узле. Ресурсы запрашиваются для максимальной конфигурации
выбранной реализации, по одному OpenMP-потоку на физическое ядро.

Просмотр очереди: `bjobs`, завершённых заданий: `bjobs -a`.
Результаты сохраняются в `results/<реализация>_<дата>/`:

- `job.out`, `job.err` — вывод задания и ошибки;
- `*_summary.txt` — время `seconds`, итерации и невязка;
- `*_solution.dat`, `*_history.dat` — решение и история итераций;
- `*_domains.dat` — разбиение для MPI.

Время измеряется внутри `solve()`. Для MPI берётся максимум по процессам.
Число процессов и фактическое число потоков выводятся в статистике.

Документация Полюса: [компиляция](https://hpc.cs.msu.ru/node/241),
[OpenMP](https://hpc.cs.msu.ru/node/254),
[MPI+OpenMP](https://hpc.cs.msu.ru/node/258).

## Проверки

Цели `make test`, `make test-omp`, `make test-mpi`, `make test-hybrid`
проверяют геометрию, оператор, сходимость и обмены между процессами.
Они запускают программы напрямую и предназначены для локальной машины
или уже выделенных вычислительных ресурсов.
