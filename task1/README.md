# Задача 1, вариант 3

Уравнение Пуассона `-Δu = 1` в трапеции с вершинами
`(0,0), (3,0), (2,3), (0,3)`, на границе `u = sin(x+y)`.

Метод фиктивных областей на прямоугольнике `[-1,4]²`, пятиточечная
разностная схема, метод сопряжённых градиентов с диагональным
предобусловливателем. Четыре реализации: последовательная, OpenMP,
MPI и MPI+OpenMP. Используется C++11.

Скалярные произведения используют компенсированное суммирование Кэхэна:
на крупных сетках обычное суммирование искажало значение функционала
и вызывало ложные перезапуски метода.

## Сборка на Полюсе

Из каталога `task1`:

```bash
module load SpectrumMPI
make all
```

Отдельные цели: `make seq`, `make omp`, `make mpi`, `make hybrid`.
Компиляторы задаются через `CXX` и `MPICXX`, по умолчанию `g++` и `mpicxx`.

## Запуск на Полюсе

Каждая команда ставит **одно задание LSF** для соответствующей реализации:

```bash
bash submit.sh seq
bash submit.sh omp
bash submit.sh mpi
bash submit.sh hybrid
```

| Реализация | Сетка | Процессов | Потоков на процесс |
|---|---|---|---|
| Последовательная | 400×600, 800×1200 | 1 | 1 |
| OpenMP | 400×600 | 1 | 2, 4, 8, 16 |
| OpenMP | 800×1200 | 1 | 4, 8, 16, 32 |
| MPI | 400×600 | 2, 4, 8, 16 | 1 |
| MPI | 800×1200 | 4, 8, 16, 32 | 1 |
| MPI+OpenMP | 400×600 | 2 | 1, 2, 4, 8 |
| MPI+OpenMP | 800×1200 | 4 | 1, 2, 4, 8 |

Параллельные конфигурации соответствуют таблицам приложения к заданию.
Последовательные расчёты на тех же сетках нужны для сравнения времени.
Всего четыре задания очереди и 26 запусков решателей: два последовательных
и по восемь для каждой параллельной реализации. Каждая конфигурация
выполняется один раз. Допуск остановки — `1e-8`.

Ресурсы выделяются для максимальной конфигурации каждой реализации:

- последовательная — одно ядро;
- OpenMP — 16 ядер одного узла; для 32 потоков используется SMT,
  по два потока на ядро;
- MPI — 32 процесса, по одному ядру, до 16 процессов на узел;
- гибридная — четыре процесса по восемь ядер, до двух процессов на узел.

MPI и гибридная версия могут использовать несколько узлов. В каждом
расчёте явно задаётся число процессов и потоков из таблицы. Задания
отправляются в очередь `normal` с лимитом три часа на всю серию одной
реализации. Это лимит планировщика, а не время отдельного расчёта.

Просмотр очереди: `bjobs`, завершённых заданий: `bjobs -a`.
Результаты сохраняются в `results/<реализация>_<дата>/`:

- `job.out`, `job.err` — вывод задания и ошибки;
- `*_summary.txt` — время `seconds`, итерации и невязка;
- `*_solution.dat`, `*_history.dat` — решение и история итераций;
- `*_domains.dat` — разбиение для MPI.

Время измеряется внутри `solve()`. Для MPI берётся максимум по процессам.
Число процессов и фактическое число потоков выводятся в статистике.

Документация Полюса: [компиляция](https://hpc.cs.msu.ru/node/241),
[OpenMP](https://hpc.cs.msu.ru/node/254),
[MPI+OpenMP](https://hpc.cs.msu.ru/node/258).

## Проверки

Цели `make test`, `make test-omp`, `make test-mpi`, `make test-hybrid`
проверяют геометрию, оператор, сходимость и обмены между процессами.
Они запускают программы напрямую и предназначены для локальной машины
или уже выделенных вычислительных ресурсов.
